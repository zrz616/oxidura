# M2 存储与任务队列

**目标**：把 M1 的内存结论落到 PostgreSQL 上：任务能被安全地抢占，提交能原子地失败。

## 交付物

- migrations：`executions` / `events` / `tasks` 三张表 + 两个部分索引（`(workflow_id) WHERE status='RUNNING'`、`(task_queue, task_type, visible_at, task_id) WHERE state=0`）（ADR-0011）。
- `PgTaskQueue`：`enqueue` / `dequeue`（单语句 `UPDATE … RETURNING` + SKIP LOCKED）/ `renew` / `complete`（DELETE）/ `reschedule`。
- OCC 提交函数：`UPDATE executions … WHERE db_record_version = $expected RETURNING next_event_id` + 同事务写事件与 enqueue（ADR-0008）。
- `examples/m2_store.rs`。

## Gate

`scripts/verify-m2.sh`：`cargo nextest run -p oxidura-store-postgres` exit 0（需 dev-pg 在跑），且下列四条集成测试全部存在：

| 测试 | 断言 |
|---|---|
| `concurrent_dequeue_no_duplicate_lease` | N 个连接并发取 M 个任务，每个 `task_id` 恰被一个连接拿到 |
| `occ_conflict_rejected` | 两个并发提交同版本 → 恰一个成功，另一个被拒；**失败方零写入** |
| `rollback_leaves_no_partial_write` | 提交中途失败后，`events` 行数与 `executions.next_event_id` 都未变 |
| `dequeue_multi_queue` | 一次调用只取指定队列；多队列签名可用（P6 预留形状） |

`examples/m2_store.rs` 直连真 PG，打印一次完整的「入队 → 抢占 → 提交」并断言结果。

## 不做

worker 循环、scanner、timer 语义、重试。

**相关**：ADR-0006 · ADR-0008 · ADR-0011
