**状态**：完成 —— `scripts/verify-m0.sh` 9/9 通过（tag `m0`）。

**目标**：一个能编译、能连库、能跑测试的空 workspace，加上仓库的契约文档。

## 交付物

- workspace（六 crate，ADR-0004）：`oxidura-core` / `oxidura-store-postgres` / `oxidura-sdk` / `oxidura-sdk-macros` / `oxidura-worker`（bin `oxidura`）/ `examples`，包名全小写，目录平铺在仓库根。
- `rust-toolchain.toml`、`rustfmt.toml`、workspace lints（含 `clippy::large_enum_variant`）。
- `scripts/dev-pg.sh`：用 Postgres.app 的 `pg_ctl` 起常驻 cluster（数据目录在仓库外，端口 55432），提供 start/stop/status/url/psql/logs。
- 脚本形态：只用 **macOS 自带 `/bin/bash` 3.2** 能跑的构造 —— 不要用 `declare -A` / `mapfile` / `${var,,}` / `&>>`；变量名后面紧跟中文时写 `${VAR}`（见下）。所有脚本 `set -euo pipefail`。
- `.env.example`（`DATABASE_URL` 的形状；唯一出处是 `scripts/dev-pg.sh url`）。
- `docs/` 全部文件存在（DESIGN / 16 篇 ADR / 11 篇 concepts / 7 篇 milestones）。

## Gate

`scripts/verify-m0.sh` 全部通过（**9 项**）：

1. `cargo build --workspace` exit 0
2. `cargo clippy --workspace --all-targets -- -D warnings` exit 0
3. `cargo fmt --check` exit 0
4. `cargo nextest run --workspace --no-tests=pass` exit 0（`--no-tests=pass` 是必需的，否则 nextest 在零测试时报错）
5. `scripts/dev-pg.sh start` exit 0
6. `psql "$DATABASE_URL" -c 'select 1'` exit 0（`DATABASE_URL` 取自 `scripts/dev-pg.sh url`；本地 `.env` 若存在则优先）
7. `grep -E 'sqlx|tokio' oxidura-core/Cargo.toml` **无输出**
8. `scripts/*.sh` 在 `/bin/bash`（3.2）下 `bash -n` 通过
9. 契约文档齐全：`AGENTS.md` + `docs/DESIGN.md` + 16 ADR + 11 concepts + 7 milestones

## 落地时踩到的坑

- **bash 3.2 + 中文字面量**：C locale 下 `"（端口 $PGPORT）"` 会把 `）` 的 UTF-8 字节并进变量名，`set -u` 报 `PGPORT…: unbound variable`。中文提示里一律 `${VAR}`。
- `examples` 这个包名 cargo 接受，六个 crate 名按 ADR-0004 原样落地。
- 开发库刻意用 **55432**：5432 留给 Postgres.app 自带集群，两边不互相踩。
