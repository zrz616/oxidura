# P6 基准与实验集

**目标**：用数字回答「Temporal 为什么要花大力气做 sticky queue 与 workflow cache」。

## 交付物

- worker 内进程 LRU + **部分重放**（只读 `event_id > 最后一条 WorkflowTaskStarted 的 event_id`）。
- sticky 队列 `sticky-<uuid>`，5s 未领取由 scanner 回落到共享队列；缓存驱逐触发点：WFT 失败、租约过期、进程退出、LRU 超限。
- `--bench` 子命令：固定一条 **10,000 事件**的历史，输出三组数字（全量 vs 部分重放）——每轮重放的事件数、重放耗时、从 PG 读的行数与字节数。
- `docs/milestones/p6.md` 的**结论段落**（数字 + 解释）。
- 实验集：`range_id` fencing 对照、transient / buffered events 对照，各留一段结论。

## Gate

`scripts/verify-p6.sh`：

1. `--bench` 产出全量 / 部分的全部三组数字，且部分重放的重放事件数**严格小于**全量。
2. **语义等价**：同一历史在两种模式下驱动到**同一终态**（这是 sticky 只是优化的证明）。
3. `p6.md` 含三组数字与解释，且两个实验各有一段结论。
4. 无 schema 变更：`grep -ri snapshot migrations/` 无输出。

## 不做

快照列（已证明不需要）、跨进程/跨机缓存共享（D12）。
