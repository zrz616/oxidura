# ADR-0002 每轮从零全量重放

**决定**：处理一个 workflow task 时，读该 execution 的**全部**历史，重跑整个 workflow 函数；历史里已发生的事件其 await 立刻返回、未发生的 await 变成 Pending 并登记命令；poll 到静止后收集命令并**丢弃内存态**。不做 sticky cache（推迟到 P6 作对照实验）。

**为什么**：历史是唯一真相。把内存态也当真相，就会出现「内存与历史不一致」这一类最难查的 bug —— 而这类 bug 的成因（重放漂移）恰恰是这个项目要教的东西。从零重放让漂移在结构上无法存在。

匹配方式取 demand-driven：每个 await 点主动从游标拉「下一条期望事件」，而不是「先吃完历史再进入 live 模式」。这样不匹配在**第一次发生时**就带着 `event_id` 报出来。

**代价**：单轮重放是 O(历史长度)（D3、D4）。这在教学规模下无关紧要，P6 用 sticky 缓存量化它到底值多少 —— 先有正确性基线，再谈优化，否则优化会掩盖重放语义的 bug。
