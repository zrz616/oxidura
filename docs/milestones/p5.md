# P5 高阶语义

**目标**：外部世界能跟 workflow 对话，并且能安全地改 workflow 代码。

## 交付物

- **signal**：`WorkflowExecutionSignaled` 事件 + AsyncEvent 缓冲 + 拉式 `ctx.wait_signal(name)` + `Client::signal`；未等待的 signal 保留（D13）。
- **query**：`tasks(task_type=QUERY)` 行、完成即删、**零事件**、结果列轮询；执行路径断言自己产出零命令（D8）。
- **`ctx.patched(change_id) -> bool`**：`MarkerRecorded`，`marker_name="Version"`（ADR-0015）。
- **child workflow**：`ctx.child_workflow(...).await`，父关闭策略 `TERMINATE`。
- **continue-as-new**：`ctx.continue_as_new(input)` + 历史长度阈值与「建议 CAN」标记（不自动执行）。
- **cancel**：`Client::cancel` → `WorkflowExecutionCanceled`（已关闭则拒）+ 向在飞 activity 写 `ActivityTaskCancelRequested` + 向子 workflow 传播。
- `WorkflowIdReusePolicy` / `WorkflowIdConflictPolicy` 的其余取值。
- 主线示例插入 `wait_signal("cancel")`。

## Gate

`scripts/verify-p5.sh`：

1. **signal**：三条按序发送 → 三条按序消费；未等待的 signal 在后续等待时仍能取到；对已关闭 execution 发送被拒。
2. **query**：执行前后 `count(*) from events where run_id = …` **不变**；只读断言（零命令）在测试中被真实触发过一次；对**已关闭**的 execution 也能 query。
3. **patched**：改代码加 `patched` → 旧历史重放通过；不改直接改动 → `replay-check` 报 `NonDeterminism`。
4. **child**：父终止 → 子以 `TERMINATE` 结束；父子各有独立 `run_id` 与历史。
5. **CAN**：超过阈值时 WFT 完成响应带建议标记；CAN 后新 `run_id`、历史从 1 开始；`workflow_execution_timeout` 跨链延续。
6. **cancel**：在飞 activity 收到取消请求；workflow 收到 cancel 并进入终态 `Canceled`。

## 不做

Update、SDK 级 cancel scope、`ctx.spawn`（D9、D10）。
