# M3 调度闭环（MVP）

**目标**：端到端跑通一条真实工作流，并且**在进程被 `kill -9` 后能无缝继续**。

## 交付物

- activity worker：拉取 → `ActivityTaskStarted` → 执行（`catch_unwind`）→ `ActivityTaskCompleted` / `ActivityTaskFailed`；默认重试（`ActivityTaskTimedOut` + `attempt + 1` + 1s 退避）→ 排下一轮 WFT。
- workflow worker：领租约 → 写 `WorkflowTaskStarted` → 读 replay 边界 → 重放 → 一个事务提交。
- **scanner**：WFT 租约过期、activity 租约过期、`workflow_execution_timeout` 三者（ADR-0012）。
- `#[workflow]` / `#[activity]` proc-macro（引擎接口到这里稳定了）。
- CLI：`oxidura start` / `worker --role` / `history` / `describe` / `replay-check`。
- 主线示例（订单履约，**只有三个 activity**）：`charge_card` → `ship_order` → `notify_customer`；示例 activity 做幂等 upsert 并打印 `attempt`。

## Gate

`scripts/verify-m3.sh`：

1. **正常路径**：起两个 worker 进程 + client，断言 execution 终态 `Completed`，且历史里三个 `ActivityTaskCompleted` 各一条。
2. **场景 A（杀 workflow worker）**：在一次 WFT 处理中途 `kill -9`，重启后断言：历史里留下孤儿 `WorkflowTaskScheduled` + `WorkflowTaskStarted`（**无** `Completed`）+ `WorkflowTaskTimedOut`，随后新一轮三件套出现，终态 `Completed`。
3. **场景 B（杀 activity worker）**：在 activity 执行中途 `kill -9`，重启后断言：同一 `activity_id` 有 `attempt=1` 与 `attempt=2` 两条 `ActivityTaskStarted`，且 `ActivityTaskCompleted` **恰好一条**。
4. `oxidura replay-check <run_id>` 对每条已关闭 execution 报 **0** 个 `NonDeterminism`。
5. `oxidura history <run_id>` 能打印出可读的事件表。

## 不做

持久化的用户 timer（`ctx.sleep` 此时只在内存测试环境里可用）、`LISTEN/NOTIFY`、可配置的 timeout 与退避、heartbeat、signal/query/child/CAN/cancel。
